# 几何与速度推导

多元素同时缩放 + 位移时，靠肉眼调参数会陷入无限轮次。这几套公式把「看着不对」转成可解的约束。数值示例来自一个 365×210 的循环演示动画（三行卡片墙缩放并横向滚动，总长 9.8s）。

## 1. 屏幕位置与速度

一个 Frame（宽 `W`，画布坐标 `X`）整体缩放 `s`（Figma 的 `SCALE_XY` 绕节点视觉中心）并位移 `Tx`，它内部局部坐标 `c` 处的子节点，屏幕横坐标为：

```
screen_x(c) = X + W/2 + (c + off − W/2)·s + Tx
```

`off` 是子节点自己的 `TRANSLATION_X`。对时间求导：

```
v(c) = (c + off − W/2)·ṡ + oḟf·s + Ṫx
```

**这条式子解释了两个常见现象**：缩放中的容器里，不同位置的子节点屏幕速度不同，离中心越远差得越多；「只在缩小没有移动」的观感来自 `(c − W/2)·ṡ` 和 `Ṫx` 反号、互相抵消。

调「速度衔接顺不顺」时，取舞台中心对应的 `c` 代入，得到的就是观众实际看到的光流速度。

## 2. 均匀缩放平铺

多行 / 多列元素同时缩放时，要让行间距始终等比、不出现镂空或重叠，就让整个阵列绕同一个原点 `P` 缩放。

每行绕自身中心缩放 `s`，中心为 `c_i = y_i + H/2`，补一个纵向位移：

```
Ty_i = (c_i − P)·(s − 1)
```

推导：绕 `P` 缩放后中心应在 `P + (c_i − P)·s`，绕自身中心缩放后中心不动仍在 `c_i`，差值即 `Ty_i`。

代入后行顶为 `s·(y_i − P) + P`，于是：

- 任意两行的间距恒等于 `s × 原始间距`，任何 `s` 下都不镂空。
- `y_i = P` 的那一行顶边完全不动，适合当锚定行。

示例：三行卡片（高 118、间距 6）取 `P = 46`，`k = c_i − P` 分别是 −65 / +59 / +183。

## 3. 锚定

前一个元素交棒给动画元素时，交界帧两者必须完全重合。已知目标屏幕坐标 `X_target`，反解位移：

```
Tx = X_target − X − W/2 − (c − W/2)·s
```

纵向同理。`s` 取交界时刻的缩放值。锚定元素的尺寸也要对上：`元素宽 × s = 目标宽`，这条决定了交界时刻的 `s`。

## 4. 补偿轨道

缩放会等比缩放圆角、描边和投影。要让视觉值保持恒定，写一条反比轨道：

```
CORNER_RADIUS(t) = R_target / s(t)
STROKE_WEIGHT(t) = W_target / s(t)
effects[i].RADIUS(t)   = R0 / s(t)
effects[i].SPREAD(t)   = S0 / s(t)
effects[i].OFFSET_Y(t) = Y0 / s(t)
```

嵌套缩放要连乘：子节点也有自己的 `SCALE_XY` 时，除以 `s_parent(t) × s_child(t)`。

**采样点要按值等分，不按时间等分。** `1/s` 是凸函数，时间等分会在 `s` 变化快的一侧产生明显偏差。做法是先算出该段两端的 `1/s`，按进度十分位取时间点，落在 `s` 变化快的一侧自然更密。实测用 19 个采样点把视觉圆角偏差压到 0.14px 以内。

投影字段走 `INDEXED_ITEM` 描述符，见 [figma-motion-api.md](figma-motion-api.md)。

## 5. 可行性判定

一段动画要走 `L` 像素、时长 `D`、入口速度 `v0`、出口速度 `v1`。平均速度是 `L/D`。

```
速度单调从 v0 过渡到 v1  ⟺  min(v0,v1) ≤ L/D ≤ max(v0,v1)
```

平均速度超出两端速度的范围时，中途必然出现比两端都快（或都慢）的鼓包，观感上是「冲一下再收住」。反解可用时长：

```
L / max(v0,v1)  ≤  D  ≤  L / min(v0,v1)
```

**先算这个再调曲线。** 实测案例：某段位移 977.86px，1.6s 的平均速度 611 px/s 高于两端的 387 和 300，任何缓动都做不出平滑过渡；把时长搜到 1.9s 才进入可行区间。花在调曲线上的两轮迭代本来可以省掉。

## 6. 从故事板姿态生成平滑路径

用户在故事板里画了一步的多个中间姿态时，把它们当作**路径上的航点**，而不是直接当关键帧。直接当关键帧会得到分段线性的速度，观感上一顿一顿。

分三层处理，把「走哪条路」和「走多快」解耦：

1. **路径**：航点按参数 `p ∈ [0,1]` 排列，位置与旋转用 Catmull-Rom 插值成平滑曲线；**宽度和模糊用线性**，样条会过冲，尺寸和模糊过冲很显眼。
2. **时间映射**：`p = ease(u)`，`u` 是该段窗口内的归一化时间。速度全部由这一层控制。
3. **采样**：`u` 等分取 7–9 个点，算出 `p`，再算姿态，写成关键帧，段间用**线性**缓动。

```js
const CR=(a,b,c,d,u)=>0.5*((2*b)+(-a+c)*u+(2*a-5*b+4*c-d)*u*u+(-a+3*b-3*c+d)*u*u*u);
function poseAt(path, p){                       // path: {q:[0,1/3,2/3,1], w:[姿态...]}
  const {q,w}=path, m=w.length-1;
  let i=0; while(i<m-1 && p>q[i+1]) i++;
  const u=(p-q[i])/(q[i+1]-q[i]), g=j=>w[Math.max(0,Math.min(m,j))];
  const cr=k=>CR(g(i-1)[k],g(i)[k],g(i+1)[k],g(i+2)[k],u);
  const li=k=>g(i)[k]+(g(i+1)[k]-g(i)[k])*u;
  return { ox:cr('ox'), oy:cr('oy'), rot:cr('rot'), w:li('w'), blur:li('blur') };
}
```

**不同角色的窗口可以不同。** 故事板的第 N 帧不一定是所有元素的同一个进度：实测的四帧故事板里，换位在第 3 帧就完成（占一步的 67%），而坠落和补位要到第 4 帧（100%）。按角色各给一个窗口，别硬套同一个进度。

## 7. 固定图层下的循环需要几个节点

Figma Motion 不能给图层顺序打关键帧，而循环轮换必然要求「最前的元素回到最后」。节点数由 z 序的单调性推出来。

设遮挡关系为「新进 < 后 < 中 < 前 < 离场」。一个元素进场后要依次占据越来越靠前的位置，它的 z 必须始终高于比它晚进场的元素、低于比它早进场的。于是**按进场先后严格递减排 z**，每一轮进场都要一个新节点。

N 个元素、N 步一循环，可见槽位 K 个：**节点数 = K + N**。实测 K=3、N=4 得 7 个节点，自下而上是「第 N 步进场 … 第 1 步进场，起始的后、中、前」。末帧由后 K 个补位节点占据 K 个槽位，与首帧的元素一一对应即可无缝循环。

## 8. 缓动数值搜索

约束明确之后，缓动就是个小规模搜索问题，不用手调。

```js
let best = null;
for (const x1 of GRID) for (const y1 of GRID) for (const x2 of GRID) for (const y2 of GRID) {
  const v = sampleFlow([x1, y1, x2, y2]);        // 按 10–20ms 采样出速度序列
  const cost = Math.max(...v) - Math.min(...v);  // 目标函数按需求换
  if (!best || cost < best.cost) best = { cost, e: [x1, y1, x2, y2] };
}
```

目标函数按用户反馈的措辞选：

| 用户说 | 目标函数 |
|---|---|
| 不要来回移动 | 回摆量为 0（硬约束，先过滤） |
| 加速要均匀 | 加速度的方差最小 |
| 不要明显加速 | 速度极差最小 |
| 要有阻尼感 | 出口斜率趋近 0，同时限制极差 |

cubic bezier 求值：给定 `t`，先用二分或牛顿法解 `x(u) = t`，再取 `y(u)`。控制点固定为 `(0,0)` 和 `(1,1)`。

## 7. 单调性与连续性检查

**回摆检查**：对每个元素按 10ms 步长算屏幕位置，累加所有与整体方向相反的位移量。目标是 0。观众对「往回退一下」极其敏感，这是最常被指出的问题。

**速度台阶**：在段交界处取前后各一个采样点，速度差除以平均速度。控制在几个百分点以内。实测定稿时某交界处是 301.5 → 300.0，台阶 0.5%。

**覆盖检查**：横向滚动的元素阵列要保证任意时刻都铺满舞台。按采样时刻算每个元素的屏幕包围盒，检查并集是否覆盖 `[0, stageW]`。

**背景暴露栅格**：在舞台上打点（3–4px 步长），统计任意时刻未被任何元素覆盖的比例，减去静止状态的基线。这是查「过渡中途露馅」最直接的指标，也能定位——把某时刻未覆盖、但静止时被覆盖的格子挑出来求包围盒，就知道缺口在哪。**先定位再修**：实测有一次凭现象猜缺口在后排，改完暴露反而上升，实际缺口在顶部条带。

### 指标要定义在可见区域、且沿真正单调的方向

回摆检查用错参照会报假警，两次实测教训：

- **用质心而非可见轮廓**：一张卡从 14.71° 转到 5.14° 时，位于裁剪线以下的部分向左摆，质心横移 −5.75px，但可见区域内的左右缘全程向右。改成「按可见带裁剪多边形后取轮廓左右缘」，回摆归零。
- **在本来就双向的方向上查单调**：卡片前移时向上、坠落时向下，纵向本就双向，套单调性检查必然报错。这类指标只对确实单向的运动有意义。

## 9. 循环

首帧和末帧必须完全一致才能无缝循环。两种做法：

- **留空白帧**：内容全部退场后停留 0.5–0.9s，下一轮从空白开始。适合有明确起止的演示动画。
- **角色轮换**：末帧由不同的节点占据与首帧相同的槽位，元素身份一一对应。适合无起止的循环轮播，见第 7 节。

第二种要按**组件身份**比对首末帧，不能只比槽位是否被占。
