# 动效判断 — 缓动、时长、节奏

来源：`emil-design-eng`（Emil Kowalski 的动效工程原则）与 `motion` skill 的 universal best practices，按 Figma Motion 的能力做了适配。**Phase B 开始前直接加载那两个 skill**，这份文档是速查和 Figma 侧的落地写法，冲突时以原 skill 为准。

## 该不该动

先按频次判断：

| 用户看到的频次 | 处理 |
|---|---|
| 每天 100 次以上（快捷键、命令面板） | 不做动画 |
| 每天几十次（hover、列表切换） | 去掉或大幅削减 |
| 偶尔（弹窗、抽屉、toast） | 常规动画 |
| 罕见 / 首次（onboarding、演示、庆祝） | 可以做表现 |

键盘触发的操作永远不加动画。Onboarding 和功能演示落在最后一档，是本 skill 的主要场景，可以做长时间轴和明显的表现。

再问目的。合法目的只有五类：空间连续性、状态指示、机制解释、操作反馈、避免突兀的出现和消失。目的只是「好看」而用户又会频繁看到，就不做。

## 从参考视频提取节奏

用户给了参考视频就先量，不要凭观感描述。

```bash
ffprobe -v error -show_entries format=duration \
  -show_entries stream=width,height,r_frame_rate,nb_frames -of default=noprint_wrappers=1 ref.mov

# 第一遍：全片均匀 16 帧，看循环结构（几个元素、周期多长、状态怎么轮换）
for i in $(seq 0 15); do t=$(awk -v i=$i 'BEGIN{printf "%.3f", i*DUR/15}')
  ffmpeg -v error -ss "$t" -i ref.mov -frames:v 1 -vf "scale=460:-1" "f$i.png" -y; done
ffmpeg -v error -i "f%d.png" -vf "tile=4x4:padding=6:margin=6" -frames:v 1 sheet.png -y

# 第二遍：锁定一次过渡，按 0.05–0.07s 步长抽 16 帧，量过渡时长
```

时间戳要用 `awk` / `printf` 格式化。`bc` 输出的 `.544` 缺前导零，ffmpeg 会拒绝。抽帧免费，一次拼图多看几个时刻。

要量出来的四件事：**周期**（每个元素停留多久）、**过渡时长**（起动到落位）、**运动方向**（往哪走、绕哪转）、**同时动还是接力**。最后一条决定整个结构。

## 同时动还是接力

多个元素换位有两种结构，观感差别很大：

- **同时动** — 所有元素在同一窗口内一起走，读作「一次转动」。
- **接力** — 每个位置先被下一个元素补上，原占位的再走，读作「排队」。

接力的好处是过程中不露出背景，代价是时长成倍拉长（四个角色各 0.30s 依次错开 0.20s，一步就要 0.90s）。**不要为了消除背景暴露而选接力。** 实测：把多余暴露压到 0 的接力版被评价为「非常不流畅、顺序不对」；改成所有元素在 0.45s 内一起走、接受 5.6pp 暴露后，评价是「变化正常流畅、前后关系衔接得上」。

背景暴露的合理基准是**故事板自己隐含的值**，不是 0。从用户画的中间帧读出最上层元素的位置，算它比静止状态多露多少，以此为目标；压得更低就是在改用户的设计。

## 进出用不同的时间映射

同一次过渡里，离场和入场的元素不该共用一条曲线。

- **离场 / 坠落** → 缓入。起步慢、逐渐加速，符合重力，也给接替的元素留出补位时间。
- **入场 / 就位** → 缓出。起步快、末端收住。

实测反例：四条路径全用缓出，前 20ms 离场卡下坠 11.6px，接替它的卡才升 5.3px，顶部裂开一条背景带。离场改成缓入 `CB(0.30, 0.10, 0.70, 0.85)` 后消失。

## 选缓动

```
元素在进场或退场？
  是 → ease-out（起步快，响应感强）
  否 →
    在屏幕内位移或形变？ → ease-in-out
    是 hover 或颜色变化？ → ease
    是匀速运动（跑马灯、进度条）？ → linear
    其他 → ease-out
```

**UI 动画不用 ease-in。** 它起步慢，正好压在用户注视最集中的那一刻，300ms 的 ease-in 下拉比同样 300ms 的 ease-out 感觉更慢。

**内置缓动太弱。** 用自定义 cubic bezier。Figma Motion 里写成 `CUSTOM_CUBIC_BEZIER`：

| 用途 | 曲线 | Figma 写法 |
|---|---|---|
| 入场 / 出现 | `cubic-bezier(0.23, 1, 0.32, 1)` | `{x1:.23, y1:1, x2:.32, y2:1}` |
| 屏内位移 / 形变 | `cubic-bezier(0.77, 0, 0.175, 1)` | `{x1:.77, y1:0, x2:.175, y2:1}` |
| 抽屉 / 大面积移动（iOS 感） | `cubic-bezier(0.32, 0.72, 0, 1)` | `{x1:.32, y1:.72, x2:0, y2:1}` |
| 匀速 / 采样轨道 | `cubic-bezier(0, 0, 1, 1)` | `{x1:0, y1:0, x2:1, y2:1}` |

需要更强或更弱的变体去 easing.dev / easings.co 找，不要凭空造曲线。

**弹簧用在物理运动上**，尤其是可能被打断的。严肃产品（金融、企业工具）不要过冲；Figma 里用 `CUSTOM_SPRING` 的 `bounce: 0`–`0.2`。

### 曲线斜率怎么算

调速度衔接时会反复用到，记住这两条：

- 入口斜率 = `y1 / x1`
- 出口斜率 = `(1 − y2) / (1 − x2)`

两者都相对于该段的平均速度。想让某段的出口速度接上下一段的入口速度，就解这两个式子。

## 定时长

| 元素 | 时长 |
|---|---|
| 按钮按压反馈 | 100–160ms |
| Tooltip、小 popover | 125–200ms |
| 下拉、选择器 | 150–250ms |
| 弹窗、抽屉 | 200–500ms |
| 演示 / 营销动画 | 可以更长 |

常规 UI 动画控制在 300ms 以内。演示类动画不受这条限制，但单段超过 2s 需要有理由，例如要让观众看清画面内容。

Figma Motion 的官方默认建议是单段 0.25–0.7s。

## Stagger

同组元素依次入场，间隔 30–80ms，默认取 40ms。间隔太长会让界面显得迟钝。

排序体现层级：标题 → 副标题 → 主内容 → 次要内容。一个表格渐显的实际排法是表头 → 侧栏容器 → 侧栏各项 → 表格各行，每项 `OPACITY 0→1` 配 `TRANSLATION_Y 6→0`，单项 216ms，起始时间依次错开 42ms。

Figma 里没有 `animation-delay`，stagger 靠每个节点自己那条轨道的起始 `timelinePosition` 错开实现。

## 进出场时长不对称

用户在决策的地方慢，系统在响应的地方快。长按删除按 2s 线性、松手 200ms ease-out。演示类动画里对应的是：状态展示可以停留久一点，状态切换要快。

## 整体气质要一致

缓动和时长要符合组件的性格。专业仪表盘要利落干脆，活泼的产品可以有弹性。同一条时间轴里的所有段应该来自同一套缓动 token，个别段偏离要有理由。

## 遮罩过渡的用法

模糊可以掩盖不完美的过渡。两个状态之间形变复杂、中间态难看时，加一层模糊或扫光遮罩过渡，比硬做形变更可控。页面切换用斜向扫光遮罩的典型时长是 400–450ms。

## 检查方法

- **放慢看。** 把时长临时拉长 2–5 倍，检查缓动手感、变换原点、多个属性是否同步。
- **逐帧看。** 协同属性之间的时序问题在全速下看不出来。
- **隔天再看。** 换一双眼睛能发现当天没注意到的瑕疵。

Figma Motion 没有浏览器 DevTools 那样的逐帧面板，对应做法是导出视频后用 `ffmpeg` 抽指定时刻的帧。

## 不要做的事

- 从 `scale(0)` 开始放大。起点太小时元素的形状和文字都是糊的，改成从 `0.9` 左右起。
- 大幅旋转、夸张回弹，除非明确要求。
- 用关键帧做可被打断的交互动画。Figma Motion 是线性时间轴，不适合做可打断的交互，这条主要影响后续把动画翻译成 Web 实现的场景。
